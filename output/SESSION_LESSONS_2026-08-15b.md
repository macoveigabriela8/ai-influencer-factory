# Session lessons, 2026-08-15 (reels 32-33) — read this before touching the pipeline

Everything below was paid for once. A fresh session should get these right on the
first attempt. Ordered by how expensive the mistake is.

---

## 1. The DM funnel: `postId: null` NEVER FIRES

A Blotato comment automation with no `postId` does not receive comment events,
despite the API documenting it as "match comments on any post".

**Evidence.** Account 63585: all 9 comment automations carrying a *published*
postId had fired (267 alone 28 times). 10 of 12 with `postId: null` had never
fired. The proof case was reel 24 — two "forgive" comments on post 6159515, the
automation active with a matching keyword, and `list_automation_logs(1005)`
returned an **empty list**: not a failed run, *no run at all*.

**Second confirmation.** Automation 263 IS scoped — to `3250679`, a *submission*
id. Publishing mints a NEW id in a different range (scheduled 3.4M vs published
6.1M), so a submission id is equally dead.

**Consequences, all live:**
- `scripts/bind_automations.py` on cron at `:17` joins scheduled→published on
  `mediaUrls` and patches in the real id. Register the media url when you create
  the automation (`registry["media"][automationId]`).
- Cross-post catch-alls are **impossible**. A keyword that must work everywhere
  needs one automation PER post.
- `daily_dashboard.dm_health()` now audits CONFIG as well as delivery, so a dead
  automation is flagged before anyone comments rather than after a broken promise.

**Diagnostic that settles it:** `triggered: 0` is ambiguous (nobody commented?).
`list_automation_logs` returning `[]` is not — the flow never started.

## 2. Source selection: the corpus is full of NEAR-DUPLICATES

These accounts repost the same script many times at wildly different play counts.
**47 such clusters** exist. The ledger's shortcode guard cannot see them — the
shortcodes differ.

    DSXucA2kT96  18,535,469   "Keep it private until it's permanent"
    DT5MoDUAL6D     461,871   same script          <- we built reel 26 from THIS
    DVEI18AgH7h     958,440   "Never start your morning..."
    DVpPFVSDIPj      27,464   same script          <- we built reel 12 from THIS

Two of the four clusters we have drawn from were entered through the weak twin,
and **using either twin burns the whole topic**.

**Fix:** `CORPUS.md` now marks every row `BEST` / `dup` / `USED-CLUSTER`. Pick
only `BEST`. Regenerate with `python3 scripts/build_corpus.py --index`.

**Ranking, in order:** vein first (family 38% / identity 33% outlier rate vs
health 9%), then comment rate *within* the vein, then cluster-BEST. Do not let a
high comment rate pull you into health — a 3.344% c-rate post in this corpus is
phlegm/digestion content.

## 3. Anchor identity drift — the bug nobody was checking for

Anchors were generated by editing the PREVIOUS anchor. nano-banana re-renders the
face every time, so error compounds per generation and the man slowly stops being
the same man. Caught by the operator's eye, not by any gate.

**Fixed:** `make_anchor.py` defaults `--from` to `CANON` (one generation, always),
writes `hops_from_canon` provenance, and emits an identity strip. `render_avatar.py`
**refuses to spend** on anything >1 hop or with no provenance.

**The general lesson:** we had gates for burned text, loudness, band detail and
transcript accuracy — and none for *is this the same person*, the one property a
character account entirely depends on. Ask what the product actually requires,
not just what is easy to measure.

## 4. The burned text is INTRINSIC to kling. Stop trying to prompt it away.

Single-variable tests, same anchor, same audio, against reel 32's 38% baseline:

| render | burn |
|---|---|
| standard + base prompt | 38% of frames, intermittent, one line |
| standard + "no subtitles, no captions, no text" | **~100%, PERSISTENT, TWO lines — WORSE** |
| ai-avatar-**pro** + base prompt | 16.7%, fainter — better, still burns, 2x price |

The negation rule held exactly as documented ("no tripod" produces tripods).
**Never add an anti-text clause to the motion prompt.**

Engine options, all checked 2026-08-15:
- kie has NO alternative: `omni-human` fails server-side (4/4 internal errors,
  free), `seedance-2` is $0.205/s (5x kling, and it re-performs the script:
  strips CTAs, drifts to Japanese, needs 12s chunks). No seedance lite tier exists.
- fal (we hold the key): OmniHuman caps at **30s**; Wan S2V is $0.10/s.
- **WaveSpeedAI InfiniteTalk** is the only viable escape: $0.03/s at 480p
  (cheaper than kling), 10-minute takes, no subtitle layer. Needs a new account.

**Probing kie model names is FREE** — failed tasks are not billed. Verified: four
failures across two models moved the balance 0 credits.

## 5. Detecting the burn: two failure modes, two detectors, and the book

- **Intermittent** text flickers → visible to a temporal-median residual.
- **Persistent** text sits IN the median → invisible to it. A residual-only
  detector reported a two-line render **0/30 CLEAN**.
- The **open book is printed text in the same band**, so brightness and edge
  density cannot separate glyphs from pages. Three attempts failed this way, one
  of them producing a 386px caption card.

**What works — the outlined-glyph test.** A burned glyph is a pale stroke with a
dark outline: a pixel >195 within 3px of a pixel <95 on the same row. Book pages
are bright but smooth and never satisfy it. Calibrated:

    reel 26 clean -> NO GLYPHS        reel 33 persistent -> found
    reel 27 clean -> NO GLYPHS        test A two lines   -> found

It is SPECIFIC but UNDER-READS the extent, so locate with it and pad.

## 6. The caption pill: size it to the TEXT, position it over the BURN

The pill was being stretched to the burn's bounds, so a one-line caption sat in a
147px box surrounded by white — "huge empty white space looks horrible".

Backwards. A snug pill is already ~77px for one row and ~150px for two, and the
burn is a single ~15px line. **Centre a normally-sized pill on the burn** and it
is covered with no inflation. Grow it only if the burn genuinely would not fit.

**Verify on the FINISHED master, not the raw clip:** detect the white pill on each
frame independently and look for glyphs outside it. That is unambiguous, and it
caught a 25px overhang that the raw-clip measurement had missed.

## 7. Method rules that keep paying for themselves

- **Calibrate every gate on known-good AND known-bad before trusting it.** Twice
  this session a threshold I guessed would have missed the exact case the gate
  existed to catch (1.6 vs the 1.40 it had to flag; 40px pad vs a 26px under-read).
- **A manual step inside a batch is a step that eventually does not happen.**
  Everything that matters is now code that exits non-zero: subtitle gate,
  identity gate, loudness assert, QuickTime auto-open.
- **Read the error BODY, not the status code.**
- **Measure the billing delta; never quote a listed price as fact.**
- **A follow-up question is not proof of error — but the operator's eye has now
  caught two defects that four automated gates missed.** Show them frames early.
