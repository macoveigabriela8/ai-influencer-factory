# RCA — every bug in the 2026-08-15 session, and the one rule that catches them all

Seven defects in one session. None cost credits, because they all surfaced on
cheap artifacts — but three of them would have blocked or corrupted a paid
render, and one had been silently broken since **reel 16**.

## The defects

| # | where | symptom | root cause |
|---|---|---|---|
| 1 | `gate0_tts.py` | 13 of 14 clean sentences "failed" at 0.71–0.74 | scored each sentence against a window **1.4x its own length**, then divided by the LONGER side. A perfect match could only reach 1/1.4 = **0.714** |
| 2 | `gate0_tts.py` | after fixing #1, scores collapsed to ~0.0 | `difflib` **autojunk** discards any element in >1% of a sequence over 200 long. On characters vs a full transcript that is every common letter |
| 3 | `qc_gate.py` | subtitle gate crashed on reel 26 | band hardcoded to `crop=1080:500:0:1150` — true for 1080x1920, **out of bounds** on kling-standard's 720x1264. Broken since the engine default changed at reel 16 |
| 4 | assembly | every music master ~6 dB quieter than its dry twin; **16.7 dB below the source** | `amix=inputs=2` normalises by input count. Nobody measured the output |
| 5 | `transcribe_sources.py` | `DbbyfX_Phmq` recorded as `Phmq`, looked untranscribed | `basename.split("_")[-1]` — a shortcode may itself contain an underscore |
| 6 | `transcribe_sources.py` | ffmpeg crash on a TikTok dump | an 11-char shortcode regex also matches the tail of a numeric id |
| 7 | Blotato PATCH | two consecutive 400s | guessed the payload shape; button titles cap at 20 chars and the body must be wrapped in `{"patch": {...}}` |

## Root causes, grouped

**A. A constant that was true once.** (#1, #3, #4) Every one encodes a fact about
the artifact — its resolution, its length, how many inputs a mixer has — as a
literal. The fact then changed, and nothing announced it. #3 is the purest case:
it was correct until the default engine moved from 1080p to 720x1264 at reel 16,
then quietly errored for a month.

**B. A measurement nobody validated in the passing direction.** (#1, #2, #4)
Each gate was written, run once against a suspect input, and believed. No one
ever asked "does this return PASS on something known good?" — which is the
single check that would have caught all three in seconds.

**C. A guessed contract.** (#7) The fix was to read the error BODY rather than
the status code; the body named the offending field both times.

**D. A string assumption.** (#5, #6) `split("_")[-1]` and a bare 11-char regex.

## The rule that catches A and B, which are the expensive ones

> **Calibrate every gate on a KNOWN-GOOD input before you trust a single
> failure. A gate that has never returned PASS is not a gate, it is an
> untested function.**

This project already had the downstream half of that rule — "when a check starts
failing everything, suspect the check" — bought for 60,460 ElevenLabs
characters. It fired correctly today: 13 failures clustered inside a 0.03 band
is a systematic scoring error, because **real defects scatter and artifacts
cluster**. But the rule is reactive. Calibrating on a known-good input is the
proactive version and it is nearly free.

Practical form, for any new gate:

1. Run it on an input you have verified BY HAND is good. It must PASS.
2. Run it on an input you have verified is bad. It must FAIL.
3. Only then run it on the unknown.
4. Derive every geometric or numeric constant FROM THE ARTIFACT (probe width and
   height, read duration, measure loudness) rather than writing a literal.
5. Assert the invariant after the operation — `build_audiobook_pt.py` already
   fails the build on >2s duration drift; the same idea applied to loudness
   would have caught #4 the day it appeared.

## Consequences already applied

- `gate0_tts.py` — word-level comparison, `autojunk=False`, exact cleaned
  substring checked first, denominator is the sentence. Reasoning in the
  docstring.
- `qc_gate.py` — the subtitle band is now a FRACTION of frame height (0.599 to
  0.859, the same fractions `anchor_check.py` uses), probed per clip.
- Assembly — **master to −14 LUFS**. Measured: his source −14.1, our dry −24.7,
  our music −30.8. Now −15.1.
- `transcribe_sources.py` — split on the FIRST underscore; shortcode regex
  rejects all-numeric ids.

## An unresolved tension worth knowing about

**The anchor fix and the subtitle gate now fight each other.** We deliberately
fill the lower third with a table, an open book and a candle so kling does not
burn fake subtitles into an empty band. An open book is *printed text*, so it
saturates a text-density detector: reel 26 flagged 34 of 34 samples and was
completely clean on inspection.

So for this anchor family the subtitle gate can only be cleared **by eye**. Do
not "fix" the threshold to make it green — that would blind it to real burned
text. Read the contact sheet.

## Related, not a bug: two limits of the engine itself

- **Anything that is not the face is frozen.** Measured on reel 26: the candle
  flame moves at ~1.0 mean frame-diff (compression noise) against ~14 for the
  mouth. Kling animates the face region of a still, full stop. The fix is prop
  choice — put things in the lower third that have no business moving (beads,
  a stone bowl, folded cloth, an unlit lamp), never a flame or running water.
- **Face size sets lip-sync quality, not model tier.** Reel 24's face was ~8% of
  frame height and read mushy; reel 26 at ~20% reads clean on the same engine.
